### What it does

Detects an unexpected destination app after a redirect and uses Accessibility to return automatically.

### Limits and notes

It is a post-jump remediation. The target page may have appeared briefly, and the requests or data exchanges that occurred before the redirect will not be revoked.

### Before use

Please only grant accessibility permissions to trusted sources; more suitable for developers or researchers, and cannot be installed directly as a normal app

## Technical notes

### Working method

**Where it starts:** ShakeGuard does not block shake before jump,<br>
**How it decides:** Instead, use Accessibility Services to record changes to the front-end app.<br>
**What it does:** After discovering that users were taken from a protected app to an unusual destination in the configuration,<br>
**Possible result:** It immediately calls return/accessible navigation to bring the user back to the original app, so it is a "skip over and pull back later" remedy.

### Coverage

Navigation-triggering｜Exceptional cross-application ad jump that has occurred; the focus is to bring users back to the original app

### Intervention point

Accessibility service + front-end application identification + automatic return
