### What it does

Uses accessibility services to read page UI nodes and match "skip/close" according to subscription rules, and then use accessibility taps/gestures to automatically skip ads.

### Limits and notes

Ads will still be loaded and displayed first; rules depend on UI nodes and page structure, and app updates, Canvas/WebView or custom-rendered interfaces may invalidate matching.

### Before use

Only grant accessibility permissions to trusted sources

## Technical notes

### Working method

**Where it starts:** GKD listens to window/page changes through Accessibility Services and reads the Accessibility Node/UI control tree exposed by the system.<br>
**How it decides:** Determines whether the target "skip/close" control appears based on the package name, page conditions, control text, resource ID, node level/selector, etc. in the subscription rules; it usually does not directly understand "this is an ad".<br>
**What it does:** During the display phase of the ad UI, call the accessibility node click or gesture capabilities to operate the target control.<br>
**Possible result:** The ad will usually still load/show first, but the "skip/close" operation is done automatically by the tool.

### Coverage

Display-only｜"skip/close" controls in splash ads that can be located through Accessibility nodes, and repeated UI that can be described by rules

### Intervention point

Accessibility services + UI accessibility nodes + rules/selectors
