### What it does

Based on the Python APK reverse/patch tool of apktool + smali, the README clearly provides a variety of Rmads advertising removal methods, which can modify the Manifest, permissions, advertising ID and advertising loader before repackaging.

### Limits and notes

A general reversing/patching tool rather than an ad-specific app, but the README explicitly provides rmads functionality. Some methods (such as removing INTERNET permissions) are very coarse-grained and will affect normal networking at the same time; repackaging may also trigger signature/integrity verification.

### Before use

Modified applications may bring signature, update, account and supply chain risks

## Technical notes

### Working method

**Where it starts:** The user hands the target APK to DTL-X, and the tool executes the selected rmads rules after decompiling it through apktool/smali.<br>
**How it decides:** Matches advertising-related content based on characteristics such as preset strings, Manifest items, advertising IDs, and loader dictionaries, such as com.google.android.gms.ad, ca-app-pub.<br>
**What it does:** Staticly modify AndroidManifest.xml, permissions, strings, and smali/ad loaders, then recompile and sign the APK.<br>
**Possible result:** The hit advertising component, advertising ID, loader or network path has been modified/disabled, so that the relevant ads of the modified app cannot be loaded or displayed according to the original process.
