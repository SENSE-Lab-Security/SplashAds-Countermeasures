### What it does

Uses LSPosed/Xposed hook advertising SDK, network and SensorManager calls to directly truncate logic during the advertising initialization/loading or shake listening phase.

### Limits and notes

Root + LSPosed/Xposed is usually required; app/SDK updates, code obfuscation, dynamic loading or native implementation may make hook invalid, and continuous adaptation is required.

### Before use

May affect system security or application stability

## Technical notes

### Working method

**Where it starts:** AdClose injects the target app via LSPosed/Xposed and monitors pre-adapted ad SDK methods, network calls, or SensorManager listener registrations.<br>
**How it decides:** When known ad SDK/sensor related classes and methods are called, the corresponding ad or shake logic is considered to be executed; the ad is not identified through the UI.<br>
**What it does:** Directly short-circuit methods, modify return values, or block/remove listening during the advertising SDK/app logic or sensor listener registration phase.<br>
**Possible result:** The advertising SDK may fail to initialize/load, or the shake listener may not be established, thus cutting off the advertising/triggering chain earlier.

### Coverage

Both (multi-layer protection)｜Open screen/in-app advertising, shake to trigger advertising

### Intervention point

LSPosed/Xposed + Advertising SDK/API hook + Sensor monitoring control
