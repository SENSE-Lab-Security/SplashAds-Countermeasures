### What it does

The Android touch shielding tool places an Overlay in a specified rectangular area and swallows touch events. It can be used to shield UI areas that are prone to accidental activationes, including sticky ads.

### Limits and notes

It is not an ad recognition tool and requires the user to manually set the area; it will also block normal interactions in the area. Scenarios such as the system gesture area, keyboard, and apps that call HIDE_OVERLAY_WINDOWS may not be covered.

## Technical notes

### Working method

**Where it starts:** The user specifies a rectangular area on the screen that needs to be protected, and One Patch creates a TYPE_APPLICATION_OVERLAY in that area; TYPE_ACCESSIBILITY_OVERLAY can also be used when accessibility is enabled.<br>
**How it decides:** It does not recognize ads, but is pre-specified by the user "Do not pass the touch here to the underlying app".<br>
**What it does:** Follow the project instructions for processing in the request, interface or jump phase.<br>
**Possible result:** The underlying app/ad cannot receive these tap/swipe events, so ad taps or jumps that rely on touch triggers in this area will not occur.

### Coverage

Navigation-triggering (input layer) | Touch triggering and accidental activationes such as taps and swiping in fixed/large advertising areas
