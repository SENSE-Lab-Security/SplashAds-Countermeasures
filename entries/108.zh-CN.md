### 能做什么

通过 HTTP(S) MITM + Rewrite / Map Local 匹配广告 API，可直接改写请求/响应或伪造本地空响应，使广告数据在进入 App 前被删除或替换。

### 限制和注意事项

需要配置规则和 MITM 证书；证书固定（certificate pinning）、QUIC/非 HTTP 流量或未进入 Surge HTTP engine 的连接可能无法改写；规则通常需要按 App/API 维护。

### 使用前提示

会接管部分网络连接或域名解析

## 技术说明

### 工作方式

**从哪里开始：**Surge 的 HTTP engine 接收经代理的 HTTP 流量；HTTPS 主机在启用 MITM 后可被解密并进入重写流程。<br>
**如何判断：**按 URL 正则、Host、请求/响应内容或脚本规则识别广告 API/广告字段，而不是判断屏幕上的广告 UI。<br>
**怎么处理：**在资源/数据返回阶段使用 Map Local/API Mock、URL/Header/Body Rewrite 或 JavaScript 脚本返回空数据、替换字段或阻断请求。<br>
**可能结果：**广告 API 或素材请求可在到达 App 前被改写/置空，因此广告可能不再展示，同时正常同域业务请求仍可保留。

### 可覆盖场景

两者（资源/数据层）｜可由 URL/响应结构精确匹配的广告 API、JSON 广告字段和广告素材请求
