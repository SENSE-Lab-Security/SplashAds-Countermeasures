### 能做什么

利用 无障碍服务 读取页面 UI 节点并按订阅规则匹配“跳过/关闭”，再用无障碍点击/手势自动跳过广告。

### 限制和注意事项

广告仍会先加载并显示；规则依赖 UI 节点和页面结构，App 改版、Canvas/WebView 或自绘界面可能让匹配失效。

### 使用前提示

请只对可信来源授予无障碍权限

## 技术说明

### 工作方式

**从哪里开始：**GKD 通过 无障碍服务 监听窗口/页面变化，并读取系统暴露的 Accessibility Node/UI 控件树。<br>
**如何判断：**根据订阅规则中的包名、页面条件、控件文字、resource ID、节点层级/选择器等判断目标“跳过/关闭”控件是否出现；它通常不是直接理解“这是广告”。<br>
**怎么处理：**在广告 UI 已展示阶段，调用无障碍节点点击或 Gesture 手势能力操作目标控件。<br>
**可能结果：**广告通常仍会先加载/显示，但“跳过/关闭”操作由工具自动完成。

### 可覆盖场景

纯展示型｜开屏广告中可由无障碍节点定位的“跳过/关闭”控件，以及规则可描述的重复 UI

### 干预位置

无障碍服务 + UI 无障碍节点 + 规则/选择器
