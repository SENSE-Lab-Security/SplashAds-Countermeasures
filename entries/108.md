### What it does

Through the HTTP(S) MITM + Rewrite / Map Local matching ad API, the request/response can be directly rewritten or the local empty response can be forged, so that the ad data is deleted or replaced before entering the app.

### Limits and notes

Rules and MITM certificates need to be configured; certificate pinning, QUIC/non-HTTP traffic, or connections that do not enter the Surge HTTP engine may not be rewritten; rules generally need to be maintained per app/API.

### Before use

Will take over part of the network connection or DNS resolution

## Technical notes

### Working method

**Where it starts:** Surge's HTTP engine receives proxied HTTP traffic; HTTPS hosts can be decrypted and entered into the rewrite process when MITM is enabled.<br>
**How it decides:** Identifies ad APIs/ad fields by URL regex, host, request/response content, or script rules instead of judging on-screen ad UI.<br>
**What it does:** Uses Map Local/API Mock, URL/Header/Body Rewrite or JavaScript scripts to return empty data, replace fields or block requests during the resource/data return phase.<br>
**Possible result:** Advertising API or material requests can be overwritten/blanked before reaching the app, so ads may no longer be displayed, while normal same-domain business requests can still remain.

### Coverage

Both (resource/data layer) | Ad API, JSON ad fields and creative requests that can be matched exactly by URL/response structure
